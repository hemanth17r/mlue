# MLUE Specification 1.2: Zero-Copy Binary Document (`.mlueb`) & Write-Ahead Log (`.wal`)

## Status: APPROVED & FROZEN
## Schema Version: 1.2
## Substrate Tier: Tier L1 (Scaffolding-Decoupled)

---

## 1. Executive Overview

MLUE 1.2 introduces native binary representations designed for direct C memory-mapping, zero-copy deserialization, sub-microsecond state snapshotting, and crash-resilient deterministic replay.

The specification defines two distinct binary formats:
1. **`.mlueb` (Binary Document Container)**: A compact, 8-byte aligned binary container for static and dynamic scene definitions. Eliminates textual JSON tokenization and memory allocation during loading.
2. **`.wal` (Streaming Write-Ahead Log)**: An append-only binary frame stream capturing simulation timestamps, user input signals, discrete collision triggers, state tree mutations, and periodic keyframe checkpoints with per-frame CRC32 integrity checks.

## 2. `.mlueb` Binary Document Specification

### 2.1 General Layout & Alignment
* **Endianness**: Little-Endian (`<`) throughout all fields.
* **Alignment**: All struct tables and string dictionary offsets are 8-byte (64-bit) aligned.
* **Integrity**: Full-file payload CRC32 checksum recorded in the header.

```
+-------------------------------------------------------------------+
| 0x00 - 0x3F : File Header (64 Bytes)                              |
+-------------------------------------------------------------------+
| Offset Table : Entity Records (num_entities * 64 Bytes)           |
+-------------------------------------------------------------------+
| Offset Table : Rule Records (num_rules * Variable Bytes)          |
+-------------------------------------------------------------------+
| Offset Table : String Dictionary Table (Length + UTF-8 Bytes)     |
+-------------------------------------------------------------------+
| Offset Table : Hierarchical State Tree Payload (Binary Tagged)    |
+-------------------------------------------------------------------+
```

### 2.2 File Header Structure (64 Bytes)

| Offset | Type | Field Name | Description |
| :--- | :--- | :--- | :--- |
| `0x00 - 0x03` | `char[4]` | `magic` | Magic identifier: `b"MLUE"` (`0x4D, 0x4C, 0x55, 0x45`). |
| `0x04` | `uint8` | `version_major` | Major version (must be `1`). |
| `0x05` | `uint8` | `version_minor` | Minor version (must be `2`). |
| `0x06 - 0x07` | `uint16` | `header_size` | Size of header in bytes (`64`). |
| `0x08 - 0x0B` | `uint32` | `env_width` | Environment width in pixels. |
| `0x0C - 0x0F` | `uint32` | `env_height` | Environment height in pixels. |
| `0x10 - 0x13` | `uint32` | `bg_rgba` | Background color packed as 32-bit RGBA integer. |
| `0x14 - 0x17` | `uint32` | `num_entities` | Total number of entity records in entity table. |
| `0x18 - 0x1B` | `uint32` | `num_rules` | Total number of rule records in rule table. |
| `0x1C - 0x1F` | `uint32` | `reserved_0` | Reserved for future 64-bit alignment padding. |
| `0x20 - 0x27` | `uint64` | `offset_entities`| Byte offset from start of file to Entity Table. |
| `0x28 - 0x2F` | `uint64` | `offset_rules` | Byte offset from start of file to Rule Table. |
| `0x30 - 0x37` | `uint64` | `offset_strings`| Byte offset from start of file to String Dictionary. |
| `0x38 - 0x3F` | `uint64` | `offset_state` | Byte offset from start of file to State Tree Payload. |

### 2.3 Entity Record Structure (64 Bytes, Fixed-Size)

Every entity is encoded as a fixed-size 64-byte struct:

| Offset | Type | Field Name | Description |
| :--- | :--- | :--- | :--- |
| `0x00 - 0x03` | `uint32` | `id_offset` | Offset into String Dictionary for entity ID string. |
| `0x04` | `uint8` | `entity_type` | `1` = `circle`, `2` = `box`. |
| `0x05` | `uint8` | `flags` | Bitmask: `bit 0` = solid, `bit 1` = active, `bit 2` = controlled. |
| `0x06` | `uint8` | `ctrl_axis` | `0` = none, `1` = `x`, `2` = `y`. |
| `0x07` | `uint8` | `reserved_1` | 8-bit alignment padding. |
| `0x08 - 0x0B` | `uint32` | `color_rgba` | Entity color packed as 32-bit RGBA integer. |
| `0x0C - 0x0F` | `uint32` | `ctrl_channel_offset` | Offset into String Dictionary for control channel string. |
| `0x10 - 0x17` | `float64` | `pos_x` | Normalized X position ($[0.0, 1.0]$). |
| `0x18 - 0x1F` | `float64` | `pos_y` | Normalized Y position ($[0.0, 1.0]$). |
| `0x20 - 0x27` | `float64` | `vel_vx` | Normalized X velocity per second. |
| `0x28 - 0x2F` | `float64` | `vel_vy` | Normalized Y velocity per second. |
| `0x30 - 0x37` | `float64` | `size_p1` | Radius (circle) or Width (box). |
| `0x38 - 0x3F` | `float64` | `size_p2` | Unused (circle) or Height (box). |

## 3. `.wal` Streaming Write-Ahead Log Specification

### 3.1 File Header (16 Bytes)
* Magic: `b"MWAL\x01\x00"` (`4` bytes ASCII `"MWAL"` + `uint8` major `1` + `uint8` minor `0` + `2` bytes pad `0x00, 0x00`).
* Initial Scene Hash: `uint64` FNV-1a hash of initial `.mlueb` scene container.

### 3.2 Frame Layout

Every event is written sequentially as a variable-length binary frame:

| Offset | Type | Field Name | Description |
| :--- | :--- | :--- | :--- |
| `0x00 - 0x03` | `uint32` | `frame_length` | Total byte length of this frame including length and CRC32. |
| `0x04 - 0x0B` | `uint64` | `tick_index` | Zero-based simulation step index. |
| `0x0C - 0x13` | `float64` | `sim_time` | Cumulative simulation elapsed time in seconds. |
| `0x14` | `uint8` | `event_type` | `1` = `INPUT_SIGNAL`, `2` = `COLLISION_TRIGGER`, `3` = `STATE_MUTATION`, `4` = `KEYFRAME_CHECKPOINT`. |
| `0x15 - ...` | `bytes` | `payload` | Frame-specific binary payload. |
| `End - 4` | `uint32` | `crc32` | CRC32 checksum computed over bytes `0x00` through `End - 5`. |

### 3.3 Event Frame Types & Payloads

1. **`INPUT_SIGNAL` (`0x01`)**:
   * `uint16` channel_count
   * Array of: `uint16` channel_name_len, `char[]` channel_name, `float32` signal_value ($[-1.0, 1.0]$).
2. **`COLLISION_TRIGGER` (`0x02`)**:
   * `uint16` entity_a_id_len, `char[]` entity_a_id
   * `uint16` entity_b_id_len, `char[]` entity_b_id
3. **`STATE_MUTATION` (`0x03`)**:
   * `uint8` mutation_action_type (`1` = `set_path`, `2` = `increment_path`, `3` = `push`, `4` = `pop`, `5` = `delete_key`)
   * `uint16` path_len, `char[]` path_str
   * `uint32` payload_len, `bytes` tagged_value_payload
4. **`KEYFRAME_CHECKPOINT` (`0x04`)**:
   * Full snapshot of all active entities and hierarchical state variables for fast random-access seek.

### 3.4 Crash-Recovery Protocol
1. Readers stream frames sequentially from offset `16`.
2. For each frame, read `frame_length`, verify `frame_length >= 25` and `frame_length <= MAX_FRAME_SIZE (16MB)`.
3. Compute `crc32(frame_data[0:frame_length-4])` and compare with stored `uint32` CRC.
4. If EOF is reached cleanly: all frames accepted.
5. If partial write or CRC mismatch occurs at byte offset $B$:
   * Reader halts, logs warning: `"Truncated WAL detected at byte offset B (frame corrupted/incomplete on crash). Recovered N valid frames."`
   * Safely replays up to the last valid frame $N$ with zero unhandled exceptions.
