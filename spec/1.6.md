# MLUE Specification 1.6: Vectorized Batch Rollout Protocol & Multi-Agent Memory Layout

## Status: APPROVED & FROZEN

## Substrate Tier: Tier L0 (Native Compiled Hardware Execution)
## Language Standard: Pure ANSI C99 / C11 (Zero External Dependencies)

---

## 1. Executive Overview

Subphase 1.6 establishes the **Vectorized Batch Rollout Protocol** for MLUE. It enables an AI agent, reinforcement learning loop, or Monte Carlo Tree Search (MCTS) algorithm to evaluate $M$ independent, isolated simulation environments in a single contiguous memory pass. 

By laying out $M$ environments contiguously in memory ($M \times N \times 64$ bytes) and iterating over entities in a cache-localized loop, MLUE eliminates Python interpreter overhead, achieving aggregate simulation throughputs exceeding $500,000\text{ ticks/second}$.

---

## 2. Contiguous Batch Memory Layout

All $M$ environment instances share identical spatial environment dimensions, but maintain completely independent entity state arrays.

```
+-------------------------------------------------------------------------------+
| Environment 0 : Entity 0, Entity 1, ..., Entity N-1  (N * 64 Bytes)           |
+-------------------------------------------------------------------------------+
| Environment 1 : Entity 0, Entity 1, ..., Entity N-1  (N * 64 Bytes)           |
+-------------------------------------------------------------------------------+
| ...                                                                           |
+-------------------------------------------------------------------------------+
| Environment M-1 : Entity 0, Entity 1, ..., Entity N-1  (N * 64 Bytes)         |
+-------------------------------------------------------------------------------+
```

* **Total Buffer Size**: $\text{BufferSize} = M \times N \times 64\text{ Bytes}$.
* **Memory Stride**: $\text{Stride}_{\text{env}} = N \times 64\text{ Bytes}$.
* **Isolation Invariant**: An entity in Environment $k$ can only interact with entities located in the offset range $[k \cdot \text{Stride}_{\text{env}}, (k+1) \cdot \text{Stride}_{\text{env}} - 1]$. Cross-environment interaction is physically impossible by pointer arithmetic.

## 4. Operational Invariants

1. **Deterministic Lane Isolation**: Stepping Environment $A$ with control inputs $\vec{u}_A$ produces zero numerical or physical bleed-over into Environment $B$ with inputs $\vec{u}_B$.
2. **Zero Dynamic Allocation (DO-178C Level A)**: `mlue_core_step_batch` performs zero `malloc()` or `free()` calls during execution. Memory is allocated once by the caller in Python/Host and reused across all simulation ticks.
3. **Linear Throughput Scaling**: Execution time scales linearly $O(M \times N)$ with near-zero per-environment invocation overhead.
