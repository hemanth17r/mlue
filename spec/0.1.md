# MLUE Specification — Phase 0.1

## 1. Overview & Objective
MLUE Phase 0.1 defines the minimal machine-oriented computational representation and execution contract for defining a single visual/computational object.

The goal of Phase 0.1 is to establish:
1. A machine-oriented format for specifying computational entities and their spatial properties.
2. A deterministic runtime engine that parses, validates, and evaluates this specification into an executable computational state.
3. A clearly decoupled presentation adapter (bootstrap scaffolding) to render the resulting state onto hardware displays.

---

## 2. MLUE Representation Schema (Version `0.1`)

The Phase 0.1 MLUE format uses a JSON-encoded data structure with the following schema:

```json
{
  "mlue_version": "0.1",
  "environment": {
    "dimensions": [400, 400],
    "background": "#F8FAFC"
  },
  "entities": [
    {
      "id": "object_id",
      "type": "circle",
      "position": {
        "x": 0.5,
        "y": 0.5
      },
      "size": {
        "radius": 0.15
      },
      "properties": {
        "color": "#1E293B"
      }
    }
  ]
}
```

### Fields:
* `mlue_version` *(string, required)*: Must be `"0.1"`.
* `environment` *(object, optional)*:
  * `dimensions` *(array of 2 positive integers [width, height])*: Resolution/bounds for the viewport environment.
  * `background` *(string)*: Hex color code (e.g. `"#FFFFFF"`, `"#F8FAFC"`).
* `entities` *(array of objects, required, non-empty)*:
  * `id` *(string, required)*: Unique identifier for the entity.
  * `type` *(string, required)*: Entity type. Phase 0.1 supports `"circle"`.
  * `position` *(object, required)*:
    * `x` *(number in [0.0, 1.0])*: Normalized horizontal center.
    * `y` *(number in [0.0, 1.0])*: Normalized vertical center.
  * `size` *(object, required)*:
    * `radius` *(number in (0.0, 0.5])*: Normalized radius relative to minimum viewport dimension.
  * `properties` *(object, optional)*:
    * `color` *(string)*: Hex color code for the fill.

## 3. Runtime Semantics & Evaluation Pipeline

The MLUE execution pipeline is strictly partitioned into three stages:

```text
[ .mlue Representation ]
          ↓
[ Loader & Validator ]  --> Validates schema, types, normalized ranges
          ↓
[ MLUE Core Engine ]    --> Resolves coordinates, bounds, computational states
          ↓
[ Bootstrap Adapter ]   --> Maps resolved state to host OS / display canvas
```

1. **Loader & Validator**: Ingests the raw payload, validates schema conformity and constraints (e.g., coordinates within normalized bounds).
2. **Core Engine**: Performs space coordinate projection and builds the immutable `EvaluationResult` containing computed entity states (bounding boxes, pixel coordinates, geometry).
3. **Bootstrap Adapter**: A replaceable driver that takes the computed `EvaluationResult` and invokes host-level APIs (e.g., standard Tkinter canvas) to display the result on screen.

---

## 4. Architectural Boundary: MLUE vs. Bootstrap Scaffolding

| Layer | Responsibility | Bootstrap / Scaffolding? |
| :--- | :--- | :--- |
| **MLUE Representation** | Defines the structured entity syntax, spatial constraints, and properties. | **No** (MLUE Native Concept) |
| **MLUE Engine** | Evaluates normalized space into concrete computational entity states. | **No** (MLUE Native Concept) |
| **Python / Tkinter** | Temporary host execution environment and window rendering canvas. | **Yes** (Disposable Scaffolding) |

The host language (Python) and host graphics subsystem (Tkinter/Win32) are temporary scaffolding. Neither dictates the core MLUE model.
