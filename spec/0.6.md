# MLUE Specification — Phase 0.6

## 1. Overview & Objective
MLUE Phase 0.6 advances the declarative architecture to support:
1. **Collision-Based Rule Triggers**: First-class detection and firing of events when two solid entities collide (`event: "collision"`).
2. **Entity Lifecycle Management**: Deactivation and removal of entities from the computational and rendering space (`"destroy_entity"` / `"deactivate_entity"`).
3. **Property Mutations**: Dynamic modification of entity properties (`"set_property"`).
4. **State Variable Condition Triggers**: Evaluating rules based on document-level state variables (e.g. win/loss thresholds: `bricks_remaining <= 0`).
5. **Emergent Breakout Capstone**: A complete Brick Breaker game composed 100% from declarative MLUE primitives without bespoke game engine code.

## 3. Semantics & Evaluation Lifecycle

On every simulation step `step(state, dt, inputs)`:
1. **Active Entity Filtering**: Entities with `active = False` are excluded from motion integration, boundary reflection, pairwise collision, and shape computation.
2. **Collision Event Recording**: During pairwise collision resolution between solid active entities, any collision between $(E_a, E_b)$ is recorded in the step's collision event set.
3. **Rule Evaluation**:
   * **Collision Rules** (`event: "collision"`): If the unordered entity pair $\{E_1, E_2\}$ is in the step's collision set, execute actions.
   * **Spatial / Property Rules** (`condition` with `entity`): If property threshold condition is satisfied, execute actions.
   * **State Variable Rules** (`condition` with `state_variable`): If state variable threshold condition is satisfied, execute actions.
4. **Action Execution**:
   * `"destroy_entity"`: Marks target entity `active = False`.
   * `"set_property"`: Updates target entity's `properties[property_name] = value`.
   * `"increment"`: Adds `amount` to state variable.
   * `"set"`: Sets state variable to `value`.
   * `"reset_entity"`: Re-initializes entity position and velocity.
