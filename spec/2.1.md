# MLUE Specification 2.1: Universal Spatial Substrate & Rich Primitives

## Status: APPROVED & NORMATIVE
## Schema Version: 2.1
## Substrate Tier: Tier L0 (Native Compiled Hardware Execution) & Tier L1 (Reference Standard Library)
## Language Standard: Pure ANSI C99 / Pure Python 3.10+ Standard Library

---

## 1. Executive Overview

Subphase 2.1 expands MLUE from 2D linear bounding boxes (`circle`, `box`) into a **Universal Spatial Substrate**. It introduces continuous line segments, swept rounded capsules, declarative state-bound typography, normalized parent-child hierarchy, and container auto-stacking.

All primitives fit cleanly into the cache-aligned 64-byte `MLUE_EntityRecord` in `runtime/native/mlue_core.h`, preserving sub-microsecond execution throughput and zero heap allocation churn (< 1 B/tick).

## 2. Declarative Schema Extensions (Version `2.1`)

### 2.1 `segment` (Linear Boundary & Divider)
Directional line segment between two normalized endpoints $(x_1, y_1)$ and $(x_2, y_2)$ with thickness.
* **Dual Utility**:
  * In Software: Section dividers, chart axes, card borders, workflow edges.
  * In Simulation: Static boundary walls, ramps, angled obstacles.
* **Schema**:
```json
{
  "id": "divider_main",
  "type": "segment",
  "start": { "x": 0.1, "y": 0.5 },
  "end": { "x": 0.9, "y": 0.5 },
  "thickness": 0.002,
  "properties": { "color": "#334155", "solid": true }
}
```
* **Invariant**: Segments are static or kinematic ($m = \infty$). Thin dynamic elements are modeled as capsules to prevent tunneling.

### 2.2 `capsule` (Swept Rounded Pill / Collider)
Minkowski sum of a line segment core of length $L$ at orientation $\theta$ centered at $(x, y)$, swept by radius $r$.
* **Dual Utility**:
  * In Software: Floating pill tabs, toggle switch tracks, filter badges, slider thumbs.
  * In Simulation: Smooth character colliders that never snag on corner edges.
* **Schema**:
```json
{
  "id": "status_badge",
  "type": "capsule",
  "position": { "x": 0.5, "y": 0.2 },
  "size": { "radius": 0.025, "length": 0.10, "angle": 0.0 },
  "velocity": { "vx": 0.0, "vy": 0.0 },
  "properties": { "color": "#10B981", "solid": true }
}
```

### 2.3 `text` (Declarative State-Bound Typography)
Non-physical informational typography entity.
* **Dual Utility**:
  * In Software: Metric cards, headers, table values, input labels.
  * In Simulation: Real-time telemetry HUD, scores, debug monitors.
* **Schema**:
```json
{
  "id": "score_display",
  "type": "text",
  "position": { "x": 0.05, "y": 0.05 },
  "template": "Score: {game.score} | Status: {system.status}",
  "size": { "font_scale": 0.02, "align": "left" },
  "properties": { "color": "#F8FAFC" }
}
```
* **Invariant**: `text` entities are excluded from kinematic broadphase collision detection. Template placeholders (`{path}` or `${path}`) are interpolated at tick resolution against hierarchical `state_variables` with zero string heap allocations per tick.

### 2.4 Normalized Spatial Hierarchy & Container Auto-Stacking
* **Hierarchy**: Any entity may specify `"parent_id": "parent_box_id"`. Child $(x, y)$ coordinates are interpreted as normalized relative offsets $[0.0, 1.0]$ within the parent's bounding box.
* **Clipping**: Optional `"clip_bounds": true` clamps child visual and interaction extents to the parent bounding rectangle.
* **Container Auto-Stacking**: A parent `box` entity can declare a `"layout"` property:
```json
{
  "id": "card_container",
  "type": "box",
  "position": { "x": 0.5, "y": 0.5 },
  "size": { "width": 0.8, "height": 0.6 },
  "layout": {
    "direction": "vertical",
    "gap": 0.02
  }
}
```
When `layout` is specified, child entities belonging to this container are automatically positioned linearly down (`vertical` / `stack_y`) or across (`horizontal` / `stack_x`), completely freeing AI models from cumulative floating-point arithmetic.

## 3. C-ABI 64-Byte Memory Layout Mapping

All entities map directly into the cache-aligned 64-byte `MLUE_EntityRecord`:

```c
#define MLUE_ENTITY_TYPE_CIRCLE  1
#define MLUE_ENTITY_TYPE_BOX     2
#define MLUE_ENTITY_TYPE_SEGMENT 3
#define MLUE_ENTITY_TYPE_CAPSULE 4
#define MLUE_ENTITY_TYPE_TEXT    5

#pragma pack(push, 1)
typedef struct {
    uint32_t id_idx;           /* Offset into string dictionary */
    uint32_t color_rgba;       /* Packed 32-bit RGBA integer */
    uint8_t  entity_type;      /* 1=circle, 2=box, 3=segment, 4=capsule, 5=text */
    uint8_t  flags;            /* bit 0: solid, bit 1: active, bit 2: controlled */
    uint8_t  ctrl_axis;        /* 0 = none, 1 = x, 2 = y */
    uint8_t  reserved_1;       /* 8-bit alignment padding */
    uint32_t ctrl_channel_idx; /* Offset into string dictionary for control channel */
    double   pos_x;            /* Circle/Box/Capsule/Text Center X, or Segment Start X */
    double   pos_y;            /* Circle/Box/Capsule/Text Center Y, or Segment Start Y */
    double   vel_vx;           /* Normalized X velocity */
    double   vel_vy;           /* Normalized Y velocity */
    double   size_p1;          /* Circle r | Box w | Segment End X | Capsule r | Text font_scale */
    double   size_p2;          /* Box h | Segment End Y | Capsule length | Text align flags */
} MLUE_EntityRecord;
#pragma pack(pop)
```

Total size: $4 + 4 + 1 + 1 + 1 + 1 + 4 + 8 + 8 + 8 + 8 + 8 + 8 = 64\text{ Bytes}$.

## 4. Closed-Form Analytical Geometry ($O(1)$ Math)

1. **Point-to-Segment Shortest Distance**:
   For point $P$ and segment from $A$ to $B$ with direction vector $\vec{v} = B - A$:
   $$t = \operatorname{clamp}\left(\frac{(P - A) \cdot \vec{v}}{\|\vec{v}\|^2}, 0, 1\right), \quad Q = A + t\vec{v}, \quad d = \|P - Q\|$$
2. **Circle vs Segment Collision**:
   Collision occurs if $d \le r + \frac{\text{thickness}}{2}$.
   Contact normal: $\hat{n} = \frac{P - Q}{d}$.
3. **Capsule vs Circle Collision**:
   Calculate distance $d$ from circle center to capsule core line segment.
   Collision occurs if $d \le r_{\text{circle}} + r_{\text{capsule}}$.
4. **Capsule vs Segment & Capsule vs Capsule**:
   Shortest distance $d$ between two line segments via clamped bilinear parameter minimization.
   Collision occurs if $d \le r_1 + r_2$.
