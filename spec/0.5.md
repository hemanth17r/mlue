# MLUE Specification — Phase 0.5

## 1. Overview & Objective
MLUE Phase 0.5 delivers the **capstone milestone of Phase 0**: proving that a complete, interactive, real-time game (**Pong**) emerges purely from declarative MLUE primitives without a single line of bespoke game engine code.

Phase 0.5 introduces:
1. **State Variables**: Document-level state storage (e.g. `score_left`, `score_right`).
2. **Relational Condition Triggers & Actions**: Universal declarative rule primitives evaluated on every simulation step:
   $$\text{Condition } (x_{\text{ball}} \le 0.02) \implies \text{Actions } \{\text{increment score\_right}, \text{reset ball position \& velocity}\}$$
3. **Emergent Pong**: The complete composition of Pong purely from general MLUE primitives.

## 3. Rule Evaluation Semantics

On every simulation step `step(state, dt, inputs)`:
1. **Condition Evaluation**:
   * Evaluates the operator (`"<="`, `">="`, `"=="`, `"<"`, `">"`) on the specified entity property (`"position.x"`, `"position.y"`, etc.).
2. **Action Execution**:
   * `"increment"`: Adds `amount` to the target named state variable.
   * `"set"`: Sets the target named state variable to `value`.
   * `"reset_entity"`: Re-initializes the target entity's `position` and `velocity`.
